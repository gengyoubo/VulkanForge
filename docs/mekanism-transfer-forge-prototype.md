# Mekanism 接收端遍历：Forge 开发原型

## 原型范围

开发服务器通过 `-PserverBaseline.transferCache` 显式启用 ASM 探针，只在能源、流体、气体网络的 `tickEmit` 内尝试复用外层接收端顺序。生产默认资源不注册该探针，普通构建不包含 smoke 源集。

为了比 Java 模型更保守，原型缓存各位置的**原始方向 Map 引用**，而不是缓存可插入量、接收端结果或平铺后的方向数组。内层方向 Map 及其中的 `LazyOptional` 仍是实时对象。对 `NetworkAcceptorCache.updateTransmitterOnSide`、`adoptAcceptors`、`deregister` 的调用在入口标记变更；下次发送时按对象身份核对外层实际遍历顺序，顺序变化则放弃快照，重新等待稳定。少于 32 个位置或变化后不足 16 次发送时走原始遍历。这是开发实验，并非直接照搬前一模拟的增量数组，阈值也是实验参数。

## 实际类行为检查

在隔离开发世界使用 Forge 47.4.28、Mekanism 10.4.16.80、Canary 0.3.3，三个独立服务端进程中都运行了真实的 `FluidNetwork.tickEmit`，使用 40 个模拟流体处理器共享同一个容量 600 的模拟储罐。对照与候选在相同网络上运行，比较每个处理器的模拟/执行调用及发送总量，并核对流体守恒。检查覆盖真实 `LazyOptional.invalidate()`、通过真实 `NetworkAcceptorCache.adoptAcceptors` 替换现有方向及添加位置，以及 `deregister`；均通过。日志还检查了能源、流体、气体三个类的发送钩子和缓存更新钩子成功安装。

限制：这没有构建实际管道和机器，也没有测试真正的网络 Tick、`updateTransmitterOnSide` 的真实世界调用、真实合并拆分流程、跨区块加载、Tick 内重入、外部修改可变视图或第三方模组。能源和气体路径只确认钩子安装，未做功能对照。返回快照后如果遍历期间发生外层结构变化，其异常及可见性可能不同；`WeakHashMap` 的生命周期和线程使用也还需审查。不能将这些检查视为完整兼容验证。

## 方法级计时

对同一真实 `FluidNetwork.tickEmit` 分别关闭和开启候选选择，共三个独立 JVM；每种端点数每个 JVM 先各预热 6×5000 次，再交替计时 6×10000 次。缓存选择关闭时，ASM 调用钩子仍然存在，因此对照不是完全未修改的 Mekanism。处理器仍是共享一个模拟储罐的简化对象；没有测真实机器、拓扑变化或整服 Tick。单位为 µs/调用，下表是每个 JVM 六轮各自的中位数：

| 进程 | 40 端点 对照 / 候选 | 256 端点 对照 / 候选 |
| --- | --- | --- |
| 1 | 2.304 / 3.197 | 17.086 / 17.628 |
| 2 | 2.594 / 2.638 | 18.826 / 17.792 |
| 3 | 3.081 / 3.069 | 23.556 / 24.017 |

方法计时波动明显，40 端点没有稳定收益；256 端点一组更快、两组更慢。全部 18 对中位配对变化分别为 +5.9% 和 +2.8%（正数表示候选更慢），不能据此推断整服收益。原型保留了实时方向 Map，因此与模拟报告中的局部更新方向数组不是同一实现，性能结果不能直接比较。

## 决定和复现

原型没有显示稳定收益，也缺少真实网络生命周期测试，因此没有构建给用户整合包使用的 jar，也没有启动或修改用户实例。可运行 `python tools/benchmark-mekanism-transfer-forge.py --forks 3`（JDK 17，已有开发世界和接受的 EULA），工具每次复制开发世界至 `build/reports/mekanism-transfer-forge/`，检查钩子、行为测试、服务端正常保存和 12 组计时。结果 `build/reports/mekanism-transfer-forge/d6d3d3f9-22ef-4966-ba47-7ff536905134/summary.json`。

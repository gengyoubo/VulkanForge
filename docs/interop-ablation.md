# 共享图像与 Semaphore 的 A / B / C / D 对照

这组实验继续使用统一 Benchmark 的隐藏 GL context、同一物理 GPU、1920×1080、RGBA8 / D32F、两帧槽和真正的 Win32 共享图像 / 外部信号量。没有 surface、swapchain 或 present；测得的是受控实验吞吐，不能作为游戏 FPS。

## 运行

先使用 Java 17 编译测试内核和导出 classpath：

```powershell
.\gradlew.bat :vulkan-lab:traceArgs
python tools/benchmark-interop-ablation.py --java '<Java17>/bin/java.exe'
```

默认测试 GL 4.3 / 4.4 / 4.5 / 4.6 与 VK 1.2 / 1.3 / 1.4，每个 API 五个独立 JVM，API 与实验顺序打乱。每个连续吞吐案例预热 1000 帧、计时至少 3 秒 / 128 帧，最后完成两帧槽。B 的开关两例保持相邻，并随机颠倒顺序。

`--preflight-only` 只执行同分辨率正确性预检。`--output` 选择新的结果目录，避免覆盖旧测量；`--summarize-only` 只从原始数据重建报告。默认报告在 `build/reports/interop-ablation/summary.md`，逐帧 CPU 时间、最大帧、最后排空、整卡 GPU 采样和内核指纹一并保存。

## A：真正无绘制的交接

| 案例 | VK 提交 | 单向交接 / 帧 | 图像布局 |
|---|---:|---:|---|
| A_GL_IDLE | 0 | 0 | 本地 GL 纹理 |
| A_SHARED_IDLE | 0 | 0 | 共享图像一直归 GL |
| A_VK_IDLE | 1 | 0 | 空 VK 命令，不访问共享图像 |
| A_HANDOFF_GENERAL | 1 | 2 | GENERAL 保持不变，仍转移所有权 |
| A_HANDOFF_ATTACHMENTS | 1 | 2 | GENERAL → 颜色/深度附件 → GENERAL |

所有图像在计时外初始化。计时内不绘制、不清屏、不复制、不后处理；每个完成帧的硬件输入装配顶点计数必须为 0。计时前后，检查两帧槽的全部 RGBA 像素和完整 D32F 深度模式没有变化。

GENERAL 与附件布局案例均保留 `glSignalSemaphoreEXT + glFlush`、VK wait、外部所有权获取和释放、VK signal，以及 `glWaitSemaphoreEXT`。A 的成本包括这些调用、必要命令提交、驱动排队与测量开销，不能将其全部称为某条 semaphore 指令的硬件执行时间。图像导入和内存分配在计时外。

## B：只去掉 16 个兼容 Draw

`B_FULL_ON` / `B_FULL_OFF` 复用原统一 Full Pipeline。相同的核心输入、GPU 剔除、透明、两次深度复制、GL 后处理和资源交接全部保留，连兼容绘制阶段的状态和资源绑定也保持相同。OFF 仅不发出 16 条兼容绘制命令。

OFF 将这 16 个 ID 记为 `INTENTIONALLY_EXCLUDED_DRAWS`，不伪造正常绘制，也不把它们算作 GPU 剔除：

```text
CAPTURED = SUBMITTED + CULLED + GL_FALLBACK + INTENTIONALLY_EXCLUDED
```

计时前后审计实际 API 参数和 GPU indirect 命令，每帧检查核心与兼容阶段硬件顶点计数。颜色与深度只和相同 ON/OFF 版本的 GL 4.6 参考比较，因为去掉兼容 Draw 本来就会改变颜色。

## C：深度复制与其依赖

Vulkan 案例保留与 Full 一样的源、目标格式和大小，以及深度附件 → 传输 → 深度附件的 layout 和屏障。`C_DEPENDENCIES_ONLY` 只执行依赖；`C_VK_COPY` 再加 VK 图像复制；`C_GL_COPY` 加最终 GL 深度复制；`C_BOTH_COPY` 保留两次复制。GL 本地另有 `C_GL_NO_COPY` / `C_GL_COPY` 控制，前者保留 FBO 绑定。

源深度在计时外初始化为三个区域的精确浮点值。每次真实复制的目标，在计时前后逐值比较；依赖控制中没有写入的目标不当作有效输出。该模式便于检查正确性，但其深度压缩状态和真正地形绘制结果可能不同，所以复制成本需在此内容条件下解读。

`VK_DEPTH_MS` 覆盖 VK 的复制前屏障、可选复制及复制后屏障；`GL_DEPTH_MS` 覆盖 GL 深度复制命令区间。完整帧差值还包括该工作与资源交接之间的相互影响。

## D：一次单向、两次单向与多次往返

一次单向交接是 GL→VK 或 VK→GL。稳态 GL→VK→GL 为一次往返、两次单向交接；不能在每帧只执行一次单向交接后仍假定图像回到 GL。

因此保留两种测量：

- `D_ONE_WAY_GL_VK` / `D_ONE_WAY_VK_GL`：用 CPU 时钟测单方向的同步完成延迟，包含录制、提交与目标完成等待。反向复位和准备均在单个样本外，不报告 FPS。
- `A_HANDOFF_ATTACHMENTS` / `D_ROUNDTRIPS_2` / `D_ROUNDTRIPS_4`：相同的无绘制工作量，每帧分别 1 / 2 / 4 次往返，即 2 / 4 / 8 次单向交接。多次往返必须增加相应提交，成本属于这个实验变量。

`B_FULL_ON` 提供完整管线参考：其交接数也是两次，但包含实际绘制、复制和后处理，不能只凭次数将其总成本归因于交接。

默认单向实验分别预热 100 次，采样至少 128 次并持续约 2 秒（包括样本外复位），报告每个样本内的完成延迟；完整原始数据保留在 `latencies.csv`。它与每例至少 3 秒的连续吞吐实验采用不同的计时合同。

## 读数边界

完整跨 API 时间线的首尾均使用 GL timestamp，不混减两个 API 的时钟；A_VK_IDLE 另使用同一 VK 时钟。局部 VK 时间戳位于命令缓冲内，无法覆盖前置外部 semaphore 的全部等待。跨 API 的时间线可能含 GPU 空闲，不能当作 GPU 活跃时间。

CPU 连续帧包含两帧槽等待、命令录制/提交和查询结果读取；报告单列 CPU P99、最长帧和最终排空，保留慢样本。微实验另拆 GL signal、VK record / submit、GL wait、fence 和 query 的 CPU 调用耗时。这些区间可能与 GPU 工作重叠，不能再和 GPU 时间相加。B 复用已有内核，仅有外层 CPU 帧数据和 GPU 通道时间；`HOST_SEGMENTS_AVAILABLE=0` 表示其内部 CPU 分段未测量，零占位不代表没有耗时。

GPU 利用率由 nvidia-smi 采样，属于整卡。验证层状态见日志，常规计时关闭验证层。时序正确性、像素一致性与五轮计时的稳定性分别评价，不因正确性通过就认为 FPS 小幅差值有统计意义。

## 本机五轮结果（2026-10-27）

RTX 3050 Laptop，7 个 API，共 310 个正式案例（280 个连续吞吐、30 个单向延迟）。结果和参数位于 `build/reports/interop-ablation/`；310 个案例全部通过检查，B 的 70 个完整颜色/深度结果与相应 GL 4.6 参考逐值一致，重复提交为 0。

VK 1.4 的五轮中位数：

| 案例 | FPS | GPU 时间线 ms | 整卡 GPU |
|---|---:|---:|---:|
| 共享图像驻留，不交接 | 21046 | 0.0041 | 39.2% |
| 空 VK 提交，不交接 | 6968 | 0.0012* | 88.7% |
| 无绘制，GENERAL 往返 | 3344 | 0.2880 | 80.9% |
| 无绘制，附件布局往返 | 3335 | 0.2912 | 79.8% |
| 完整流程，兼容 Draw 开 | 1777 | 0.5532 | 90.0% |
| 完整流程，兼容 Draw 关 | 1775 | 0.5560 | 89.6% |

\* 空 VK 提交的 GPU 数值只覆盖 VK 命令缓冲内部，不包括 CPU 提交、GL 查询、fence 或命令缓冲前后的驱动工作，不能把 0.0012 ms 当成该案例完整帧成本。其余跨 API 行均为同一 GL 时钟上的首尾跨度。

A 的无绘制附件往返，VK 1.2 / 1.3 / 1.4 分别为 0.2902 / 0.2913 / 0.2912 ms。GENERAL 与附件转换的配对差值在 VK 1.4 约 0.0021 ms，因此这批数据没有显示附件布局转换是主要开销。无绘制实验仍保留测量、提交和驱动等待，约 0.29 ms 是整条交接链的时间跨度，不能全部归为 semaphore 指令本身。

B 的 VK 1.4 兼容阶段 GPU 时间从 0.003848 ms 降至空阶段 0.000692 ms；关闭后，同轮 FPS 变化中位数为 +0.4%，未看到明显的整体吞吐收益。GL 4.6 的开 / 关为 3605 / 3650 FPS。保留完整状态和资源绑定时，这 16 个兼容 Draw 不是本实验的主要性能差距来源。两列独立中位数与同轮配对中位数可能方向不同，原始五轮差值一并保留。

C 的 VK 深度复制及其屏障约 0.0685 ms，只有依赖约 0.0006 ms；GL 复制区间约 0.0644 ms。同时加入两次复制时，相比依赖控制，完整时间线的同轮增量中位数为 0.1205 ms。这证明这批内容下实际复制有可测成本，局部区间与完整帧差值不能直接相加。

D 的 1 / 2 / 4 次无绘制往返分别为 3335 / 2865 / 2232 FPS，时间线为 0.2912 / 0.3378 / 0.4396 ms。交接越多越慢，但不是简单倍增。单向同步完成延迟 P50 分别为 GL→VK 0.1637 ms、VK→GL 0.1626 ms，与流水线吞吐采用不同的测量合同。

另用相同内核独立延长 A 的三个案例至各 12 秒，排除前 2 秒和末尾 0.3 秒后，得到共享驻留 GPU 37.3%、空 VK 提交 88.3%、无绘制往返 80.6%；往返时间线仍为 0.2932 ms。高占用现象不只来自前一个案例的短暂采样残留。由于硬件顶点计数为 0 且没有 Draw，这些整卡读数不能解释为实体/像素着色工作已饱和；高频查询、提交、驱动工作及等待的具体贡献仍需进一步分离。
